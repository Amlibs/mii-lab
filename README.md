# Доставка товаров по магазинам со склада (JADE)

Многоагентная система на JADE, которая составляет расписание доставки заявок со складов
в магазины так, чтобы суммарные затраты на пробег были минимальными. При этом учитываются:

- временное окно приёма товара у каждого магазина;
- грузоподъёмность машин;
- занятость машин по интервалам: погрузка → дорога → разгрузка → дорога обратно;
- несколько складов, у каждого свой пул машин. Любой склад может выполнить любую заявку, остатки на складах не учитываются.

Пул заявок читается из файла и обрабатывается пакетом. Результат записывается в `report.html`.

## Быстрый старт

Нужны **JDK 21+** (проект делался на JDK 23) и **IntelliJ IDEA**. Библиотеки `jade.jar`
и `gson-2.13.1.jar` уже лежат в папке `lib/` и подключены к проекту.

1. Откройте папку проекта в IDEA (**File → Open**).
2. Если IDEA попросит указать SDK: **File → Project Structure → Project → SDK** (можно нажать *Download JDK*).
3. **Build → Build Project**.

Сборка обязательна, если запускаете не из IDEA, а через `.bat` или консоль: `java` запускает
только скомпилированные классы из `out\production\rizblabmac`. Этой папки нет в Git, а после
изменений в коде в ней лежит старая версия. При запуске зелёной стрелкой IDEA собирает проект сама.

Собрать без IDEA, из консоли в папке проекта (нужен `javac` из JDK):
```
dir /s /b src\*.java > sources.txt
javac -encoding UTF-8 -d out\production\rizblabmac -cp "lib\*" @sources.txt
```
В PowerShell первая строка выглядит так:
`Get-ChildItem src -Recurse -Filter *.java | % FullName | Out-File sources.txt -Encoding ascii`

### Вариант 1. Всё на одном компьютере, одной кнопкой

Запустите класс **`delivery.LocalMain`** (зелёная стрелка рядом с `main`).

Откроется окно JADE, в консоли появится ход переговоров. В конце в корне проекта
будет записан **`report.html`**, его можно открыть в браузере.

Без IDEA, из консоли в папке проекта после сборки:
```
java -cp "out\production\rizblabmac;lib\*" delivery.LocalMain
```

### Вариант 2. Сервер и клиенты

| Компьютер | Что запустить | Аргументы | Скрипт |
|---|---|---|---|
| 1 | `delivery.ServerMain` | *(пусто)* или `<свой IP>` | `run\server.bat` |
| 1 | `delivery.ClientMain` | `127.0.0.1 trucks` | `run\client_trucks.bat` |
| 2 | `delivery.ClientMain` | `<IP компьютера 1> stores` | `run\client_stores.bat` |

Порядок запуска: сначала сервер, потом клиенты в любом порядке. Переговоры начнутся
автоматически, когда на связи будут все магазины из заявок и все машины.
`report.html` появится на **сервере**.

**В IDEA:** *Run → Edit Configurations → + → Application*. Укажите *Main class* и
*Program arguments* из таблицы и создайте три конфигурации («Сервер», «Машины», «Магазины»).
Для проверки на одном компьютере у всех клиентов можно указать `127.0.0.1`.

**Скриптами:** откройте `.bat` в блокноте и впишите IP в `MY_IP` / `SERVER_IP`.
Скрипты берут классы из `out\production\rizblabmac`, поэтому проект перед этим нужно
собрать в IDEA.

**Два компьютера: что проверить**
- Компьютеры в одной сети. IP компьютера 1 можно узнать командой `ipconfig` (IPv4-адрес).
- На компьютере 1 брандмауэр Windows пропускает Java. При первом запуске появится запрос, нажмите «Разрешить»; нужен порт **1099**.
- Если на компьютере несколько сетевых адаптеров (VirtualBox, VPN), передайте серверу его IP явно: `ServerMain 192.168.1.10`. На клиенте свой IP можно передать 4-м аргументом.
- На обоих компьютерах должна быть **одна версия кода**: агенты обмениваются объектами `Order` и `Trip`.

## Агенты

| Агент | Сколько | Где запускается | Что делает |
|---|---|---|---|
| **Склад** (`WarehouseAgent`) | по одному на склад | сервер | Хранит данные склада и знакомит с ними свои машины. **Первый склад в файле — координатор**: публикует заявки, считает раунды, запускает этап 2, проводит контрольную проверку и пишет отчёт. |
| **Авто** (`TruckAgent`) | по одному на машину | клиент «Машины» | Считает, может ли он взять заявку и сколько это будет стоить. Ведёт своё расписание рейсов, проверяет конфликты, на этапе 2 передаёт заявки другим машинам и принимает их. |
| **Магазин** (`StoreAgent`) | по одному на магазин | клиент «Магазины» | Собирает предложения машин, выбирает самое дешёвое и держит остальные как запасные. |

Посредника между машинами и магазинами нет: машины отправляют предложения напрямую магазину.
Агенты находят друг друга через DF (службы `warehouse`, `coordinator`, `truck`, `store`).

## Как работает

### Этап 1. Распределение заявок (переговоры по типу Contract Net)

1. Координатор отправляет каждую заявку всем машинам (`CFP`). Ответ машины уходит
   напрямую магазину заявки.
2. Каждая машина считает рейс от **своего** склада: погрузка, дорога, ожидание окна (не больше 60 мин),
   разгрузка, возвращение до закрытия склада. Проверяет вес и пересечение по времени
   со своими уже взятыми рейсами. Если рейс подходит, она отправляет `PROPOSE` с рейсом и ценой,
   если нет — `REFUSE`.
3. Магазин ждёт ответов всех машин (или 3 с после первого ответа), выбирает **минимальную стоимость**
   и отправляет `ACCEPT_PROPOSAL`. Остальные предложения он оставляет как запасные.
4. **Предотвращение конфликта.** Машина могла за это время взять другую заявку на то же
   время. Поэтому при `ACCEPT` она **перепроверяет** своё расписание и отвечает
   `INFORM` (рейс забронирован) или `FAILURE` (конфликт). Получив `FAILURE`, магазин переходит к следующему
   по цене запасному предложению. Все такие случаи печатаются в консоль.
5. Нераспределённые заявки координатор публикует заново (до 3 раундов, пока есть прогресс).

На этапе 1 каждый рейс везёт одну заявку, но машина может сделать несколько рейсов за день.

### Этап 2. Улучшение: машины передают заявки друг другу

1. Каждая машина предлагает другим машинам свои рейсы с одной заявкой, начиная с самого дорогого.
2. Получатель пробует вставить эту заявку **попутно** в свой рейс (несколько магазинов
   без возвращения на склад; перебираются все позиции вставки) или сделать отдельный рейс.
   В ответ он присылает, на сколько вырастут его затраты.
3. Передача совершается, только если она **дешевле**, чем рейс у отдающей машины, и выполнима
   (вес, окна, нет пересечений). Подтверждение двухфазное: отдающая машина удаляет свой рейс
   только после `INFORM` получателя. Если получатель ответил `FAILURE` (конфликт), отдающая машина
   пробует следующее предложение.
4. Магазины получают уведомление о новом времени доставки.
5. **Условие остановки:** раунд, в котором не было ни одной передачи, или 5 раундов.

### Стоимость и время

- Расстояние — евклидово, по координатам (км). Стоимость рейса = км × руб./км машины.
- Время в пути = км / скорость, округляется вверх до минут.
- В конце координатор собирает расписания машин и выполняет **контрольную проверку**:
  каждая заявка назначена ровно один раз, окна соблюдены, вес не превышен, рейсы одной машины
  не пересекаются.

## Входные данные (`data/`)

Время записывается как `"ЧЧ:ММ"`, координаты в км, вес в кг.

**`warehouses.json`** — склады. Первый в списке — координатор.
```json
{ "name": "Склад-1", "x": 0, "y": 0, "workFrom": "08:00", "workTo": "20:00", "loadingMinutes": 20 }
```

**`trucks.json`** — машины и склад, к которому приписана каждая.
```json
{ "name": "Авто-1", "warehouse": "Склад-1", "capacityKg": 1000, "speedKmh": 50, "costPerKm": 20 }
```

**`stores.json`** — магазины.
```json
{ "name": "Магазин-1", "x": 12, "y": 8, "unloadingMinutes": 20 }
```

**`orders.json`** — пул заявок. Окно приёма указывается в заявке. У заявок одного
магазина оно одинаковое.
```json
{ "id": "З-1", "store": "Магазин-1", "windowFrom": "10:00", "windowTo": "14:00",
  "items": [ { "product": "Молоко", "weightKg": 200 }, { "product": "Хлеб", "weightKg": 100 } ] }
```

Файлы проверяются при загрузке: обязательные поля, неотрицательные числа, уникальные имена,
окно `from < to`, существование магазинов и складов, на которые есть ссылки. Если ошибка
есть, программа выведет файл, запись и причину и не запустится. Предупреждения (например,
заявка тяжелее любой машины) выводятся, но запуску не мешают.

Каждому участнику нужны только свои файлы:

| Кто | Файлы |
|---|---|
| сервер | `warehouses.json`, `orders.json` |
| клиент «Машины» | `trucks.json` |
| клиент «Магазины» | `stores.json` |

Остальные данные агенты получают сообщениями.

## Выходные данные

- **Консоль:** ход переговоров, конфликты и их предотвращение, передачи на этапе 2,
  итоговое расписание и затраты до и после улучшения.
- **`report.html`:** итоговое расписание по складам и машинам с временной шкалой рейсов,
  таблица по заявкам, затраты после этапа 1 и этапа 2 и результат контрольной проверки.

## Ограничения и упрощения

- Заявки обрабатываются пакетом. Появление новых заявок в течение дня не моделируется.
- Распределение жадное: кто первым подтвердил, тот и везёт. Этап 2 частично исправляет это,
  но глобальный оптимум не гарантируется.
- На этапе 2 машины отдают только рейсы с одной заявкой. Рейс, собранный из нескольких
  заявок, дальше не перераспределяется.
- Дороги не моделируются: расстояние считается по прямой между координатами.
